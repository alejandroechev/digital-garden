There is a level of abstraction just above the code that seems the right starting point when interacting with AI. It is not at the level of spec or requirements but at the level of the "shape" of the code, the APIs ans there interaction at a "module" level. Is hard to be precise on how to describe this.

Sequence diagrams, pseudocode, data models seem to be the right primitives for this level. But they are only a starting point. Only when a true full implementation is ready you can assess the original idea an iterate.

By starting at this level and not from the first code generated by AI you are more in the loop. More aware of subtleties in the code that we tend to miss when just reviewing.

Can this be systematized in some way? What tooling would help with this. The temptation to ask the agent from the spec to work is always there. But my experience is an implementation first baked by an AI will always feel foreign. Even after iterating there are some first principles that will be hard to modify.

When we search the coding deaign space, if we give the agent the first move in the space we will tend to hill climb from that starting point, reaching some local optima than wont be our own. If we set the starting point it is much more likely that whatever local maxima we reach will have echoes to that starting point, and thus will be a descendant of our own idea. 

Is this concern about the shape of the code really needed? The software factory view of AI development seems to disagree with this. In the software factory model only functionality mattets. What you verify is functionality. Aesthetics and shape are secondary, probably never looked or evaluated. But I still dont buy that software can only be measured by functionality. That maybe true for one shot softeare, one iteration of the game. The moment that software becomes multi iteration and spans time and people, the moment the shape becomes important. An elegant implementation will make things easier in the future. It will allow the code to grow healthy. It will help fight the inevitable rise of complexity. An elegant implementation will specify the right abstraction to keep building.

Can agents build good, elegant abstractions. Maybe. But I am not sure we can automatically validtae this. There is no deterministic verification for this. The deisgn space of software is too large. To gain the trust from us, an agent will have to repeatedly and consistently prove its ability to implement and elegant abstraction. But even in this case, it feela that elegant agent + elegant human, interacting, discussing, designing together will be able to build something better. We will have different strengths that combined will make the sum of the parts much greater.

In the end its all about the vision of augmentation vs automation. Automating code generation is tired. Augmenting humans to build better and more elegant abstractions is wired.
